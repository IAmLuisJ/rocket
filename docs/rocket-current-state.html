What The Docs Promise

.agent/prd/PRD.md, .agent/prd/SUMMARY.md, and README.md agree on a two-part product: scaffold applications, then run an observable AI development loop from the terminal.

Scaffold

rocket new should create a production-ready Web App or Website template, install dependencies, initialize git, and create the .agent/ structure.

Loop

rocket loop should pick a task, run an AI backend iteratively, stream output, detect completion, save history, and append progress logs.

TUI

The terminal UI should feel like Rocket: task-first, visible iteration state, clear pause/skip/quit controls, and a completion report users can trust.

Why It Feels Off

The product is conceptually coherent, but the runtime behavior has two competing centers of gravity.

TypeScript loop

  • runLoop is the current TUI engine used by RocketLoopApp.
  • It starts the next incomplete task by default and uses --select for manual choice.
  • Caffeinate ownership is in the runner, with --no-caffeinate passed through from the command.
  • It saves history/logs with separate project-root and agent-dir ownership.

Shell loop

  • rocket.sh preserves the richer shell behavior from the previous script.
  • The old script path remains as a compatibility wrapper.
  • Shell UI text, notifications, help output, and log headings are Rocket-branded.
  • Shell and TypeScript tag parsers accept Rocket tags and legacy promise tags.

Recommended Finish Plan

The shortest path is to preserve the known-good shell loop behavior while making the TypeScript CLI/TUI the clean product entry point.

Stabilize the test gate

Implemented for focused loop suites. Continue using the full test suite as the merge gate.

Fix loop path ownership

Implemented by passing projectRoot through the command and TUI into the runner.

Refactor Ralph to Rocket

Unify signal tags

Chosen model: keep the TypeScript Ink runner as the CLI/TUI engine and ship rocket.sh as the standalone shell runner.
